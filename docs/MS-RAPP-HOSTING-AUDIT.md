## Phases

Each phase is one pull request to `staging`, gated before merge.

1. **CommunityRAPP.** Host it in this repository with its MIT notice and source commit. Repoint both Hippocampus
   installers and the root `azuredeploy.json`. Gate: a clean-machine install of each installer in CI.
2. **Azure tier.** Repoint `rapp_ai/install.sh`, `install.ps1` and `rapp_ai/azuredeploy.json` at `rapp_ai/` here.
   Gate: a clean-machine install, and an ARM template validation.
3. **Beta and scripts.** The store index, the workshop agent's allowed URLs, the metrics owner default, the two
   renamed beta agents.
4. **Docs.** Repoint every remaining link.
5. **Lock it.** Extend `tests/test_microsoft_release_identity.py` so any runtime file (`*.sh`, `*.ps1`, `*.cmd`,
   `*.py`, `*.mjs`, `*.json` outside `state/` and `reports/`) fails if it names the personal account, with the
   kept-on-purpose list above as the only exceptions.

The personal repositories keep working throughout. This repository becomes the source; the old URLs are not
removed by this work.

## Rules that apply

- Installers are sacred: every change is tested end to end on a fresh machine.
- The two install paths (`install.sh` and `community_rapp/install.sh`) never cross-contaminate.
- The Brainstem kernel is not edited here.
- Promotion to production is one pull request from `staging`, opened and merged by a person.
