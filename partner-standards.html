AIBAST Agent Library

How we research and verify every agent listing

This page documents the standard we hold ourselves to when adding an agent to the AIBAST Agent Library — whether it's a Microsoft first-party agent or an agent from a partner's own library. It exists so anyone reviewing our catalog, and any partner considering being featured, can see exactly how an entry earns its place and what it does and doesn't claim.

1Every entry has a single, dedicated source

Each agent links to its own primary page — a dedicated Microsoft Learn article for first-party agents, or the partner's own public listing for partner agents. We do not attach a generic multi-agent overview page to a specific agent and call it "dedicated" documentation. If a distinct agent doesn't have its own page, it is left out of the catalog rather than forced in against a shared or mismatched page.

2Every source is fetched and read, not assumed

Before an entry is published, we fetch the live source page directly (not just a search-result snippet), confirm it resolves (HTTP 200), and read the actual content to confirm it describes the agent being listed. Search summaries are used to find candidates, never as the final source of truth.

3Descriptions are paraphrased, never copied

Every description, "what it does," and "problem it solves" is written in our own words, summarizing what the source page states. We do not reproduce a partner's marketing headline or promotional copy verbatim.

4Quoted outcomes are explicit, verbatim, and labeled

If we include a quantified benefit (for example, "10–20% higher win rate"), it is because the source page states that number explicitly for that specific agent — quoted as written, never estimated, rounded, or invented by us. Every such figure is labeled as reported by its source and explicitly not independently verified by AIBAST.

5Lifecycle labels reflect the current page, not history

"Preview" or "GA" labels are only applied when the current source page explicitly states that status today. A feature's status in an older slide deck, roadmap announcement, or blog post is not presented as its current lifecycle. Every catalog records a snapshot_date so staleness is visible and re-verification is expected on a regular cadence.

6Partner listings stand on their own — no competitive framing

Partner agents are curated to show breadth and real ideas from across the Microsoft ecosystem, not to duplicate or compete with AIBAST's own catalog under a different label. We deliberately avoid picking partner agents that just restate something AIBAST already has, and we never frame a partner's agent as "AIBAST vs. the partner." Each entry is explained on its own merits: what it does, the problem it solves, and who it's for.

7Attribution and partner review

Every partner entry credits the partner by name and links directly back to their own listing. Before a partner catalog is promoted to the production Microsoft-hosted release, the partner is given the opportunity to review the selection, the paraphrased descriptions, and the attribution, and to request changes.

Why this matters A catalog is only useful if it can be trusted. These standards exist so that anyone — a partner, a Microsoft field seller, or another contributor — can independently check our work against the same primary sources we used, and expect the same answer every time.
